# YouTube → Blog 변환기 — 서버 실행 방법

유튜브 링크를 입력하고 **전송**을 누르면, 영상 자막을 분석해서 **복사 후 바로 게시할 수 있는 블로그 글**을 만들어 주는 웹 페이지입니다.
(Node.js + Express / 글 작성 AI: **Google Gemini 무료** 또는 Anthropic Claude 유료 중 선택)

---

## 1. 준비물

| 항목 | 내용 |
|---|---|
| Node.js | **20.12 이상** (22 LTS 권장). 확인: `node -v` |
| AI API 키 (둘 중 하나) | **[무료] Gemini API 키** — https://aistudio.google.com/apikey <br> [유료] Claude API 키 — https://console.anthropic.com/settings/keys |

### Gemini API 키 무료 발급 방법 (1분)

1. https://aistudio.google.com/apikey 접속 → Google 계정으로 로그인
2. 약관 동의 후 **API 키 만들기(Create API key)** 클릭
3. 생성된 키(`AIza...`로 시작)를 복사

> 신용카드 등록 없이 무료로 사용할 수 있습니다. 무료 티어에는 **분당·일일 요청 수 한도**가 있습니다(개인 블로그 용도로는 보통 충분). 정확한 한도는 https://aistudio.google.com/rate-limit 에서 확인할 수 있습니다.
>
> ⚠️ 무료 티어에서 보낸 내용(영상 자막 등)은 Google이 서비스 개선에 활용할 수 있습니다. 공개된 유튜브 영상을 다루는 용도라면 큰 문제는 없지만 참고하세요.

## 2. 설치 및 실행 (처음 한 번)

### ① 프로젝트 폴더로 이동

```bash
cd /home/youtubeToBlog
```

### ② 패키지 설치

```bash
npm install
```

### ③ 환경변수 파일(.env) 만들기

```bash
cp .env.example .env
```

`.env` 파일을 열어 발급받은 키를 입력합니다.

```env
GEMINI_API_KEY=AIza발급받은_키
PORT=3000
```

> `.env` 파일은 `.gitignore`에 포함되어 있어 Git에 올라가지 않습니다. API 키는 절대 외부에 공유하지 마세요.

### ④ 서버 실행

```bash
npm start
```

아래 메시지가 나오면 성공입니다.

```
✅ YouTube → Blog 서버 실행 중: http://localhost:3000
   AI: Gemini (gemini-3.8-flash → gemini-3.5-flash-lite)
```

### ⑤ 브라우저에서 접속

http://localhost:3000

> WSL에서 실행한 경우에도 Windows 브라우저에서 `http://localhost:3000` 으로 바로 접속할 수 있습니다.

## 3. 사용 방법

1. 입력창에 유튜브 링크를 붙여넣습니다.
2. (선택) 문체를 고릅니다 — `친근한 해요체` / `정중한 합니다체`
   - **분량**: `자세히 (내용 빠짐없이)`(기본)는 영상의 모든 내용을 영상 길이에 비례한 분량으로 풀어 씁니다. `핵심만`은 주요 주제 위주로 짧게 씁니다.
   - **영상 장면 이미지 넣기**를 켜 두면 글 중간중간 맥락에 맞는 영상 장면 캡처가 들어갑니다. (아래 "영상 장면 캡처 설정" 필요)
3. **전송** 버튼을 누르면 아래에 블로그 글이 실시간으로 작성됩니다. (영상 길이에 따라 약 10초~2분)
4. 완성되면 복사 버튼으로 블로그에 붙여넣습니다.

| 버튼 | 용도 |
|---|---|
| **제목 복사** | 블로그 에디터의 제목 칸에 붙여넣기 |
| **본문 복사** | 네이버 블로그 · 티스토리 등 일반 에디터에 붙여넣기 (소제목·굵게·목록·표 서식 유지) |
| **Quill용 복사** | Quill 에디터에 붙여넣기. 제목·굵게·목록·인용·링크가 유지되고, Quill이 지원하지 않는 표는 글머리 목록으로, 구분선은 빈 줄로 바뀝니다. 제목·목록 앞뒤에 빈 줄을 넣어 읽기 좋게 맞춥니다 |
| **마크다운 복사** | 마크다운을 지원하는 블로그 (velog, 티스토리 마크다운 모드, GitHub 블로그 등) |
| **HTML 복사** | 에디터의 HTML 모드에 붙여넣기 |
| **다시 생성** | 같은 영상으로 글을 새로 작성 (문체를 바꿔서 다시 만들 때도 사용) |

> 장면 이미지는 **모든 복사 버튼**(본문 · Quill용 · 마크다운 · HTML)에 이미지 데이터로 함께 들어갑니다. 마크다운 복사에서는 `![캡션](data:image/jpeg;base64,...)` 형태로 들어가며, project0 CKEditor처럼 마크다운을 변환하는 에디터에 붙여넣으면 이미지가 자동 업로드됩니다. 이미지가 빠지는 에디터에서는 미리보기 이미지에 마우스를 올리면 나오는 **이미지 저장** 버튼으로 받아서 올려 주세요.

**지원하는 링크 형식**

- `https://www.youtube.com/watch?v=영상ID`
- `https://youtu.be/영상ID`
- `https://www.youtube.com/shorts/영상ID`
- `https://www.youtube.com/live/영상ID`, `m.youtube.com`, 영상 ID(11자리)만 입력해도 됩니다.

> 자막(자동 생성 자막 포함)이 있는 영상만 변환할 수 있습니다. 외국어 영상도 한국어 글로 작성됩니다.

## 3-1. 영상 장면 캡처 설정 (선택)

글 중간에 넣을 **영상 장면을 캡처**하려면 프로그램 두 개가 필요합니다. 설치하지 않아도 글 작성은 정상 동작하며, 장면 이미지만 빠집니다.

| 프로그램 | 역할 |
|---|---|
| **yt-dlp** | 유튜브 영상 스트림 주소 가져오기 |
| **ffmpeg** | 해당 시점의 장면 한 장만 잘라 이미지로 저장 (영상 전체를 내려받지 않음) |

**설치 (WSL / Ubuntu)** — root 계정이 아니면 명령 앞에 `sudo`를 붙이세요.

```bash
apt update && apt install -y ffmpeg
```

```bash
curl -L https://github.com/yt-dlp/yt-dlp/releases/latest/download/yt-dlp_linux -o /usr/local/bin/yt-dlp && chmod +x /usr/local/bin/yt-dlp
```

설치 후 **서버를 재시작**하면 시작 메시지에 `장면 캡처: 사용 가능`이 표시됩니다.

**동작 방식**

1. AI가 글을 쓰면서 이미지가 있으면 좋을 곳(3~6곳)에, 바로 위 문단 내용을 영상에서 설명하는 **구간**(예: 3:10~3:40)을 표시합니다. (자막을 15초 단위 시각으로 나눠 보내서 구간을 촘촘하게 적을 수 있음)
2. 글이 끝나면 서버가 그 구간(앞뒤 20초 여유 포함)에서 **화면이 바뀌는 지점(컷)** 을 찾아, 서로 다른 화면마다 한 장씩 **후보 장면 최대 6장**을 캡처합니다. (`cache/frames/`에 저장, 같은 장면은 다시 캡처하지 않음)
   - 말하는 사람 화면 사이에 몇 초만 나오는 도표·자료화면도 후보에 들어갑니다. 컷 감지는 360p 영상의 해당 구간만 읽어서 빠르게 처리합니다.
   - 후보 순위: 자막에서 그 문단·캡션과 **같은 이야기를 하는 화면** > AI가 적은 구간 안의 화면 > 짧게 끼워 넣은 자료화면
   - 컷 감지가 안 되면 자막이 맞는 순간과 구간 안 고른 간격으로 후보를 뽑습니다.
   - 검은 화면·페이드 중인 빈 화면은 AI에게 보내기 전에 걸러 냅니다.
   - 장면 이미지는 모두 **WebP** 형식입니다. (같은 화질에서 JPG보다 30~40% 작음) "이미지 저장"과 복사·붙여넣기 모두 WebP로 들어갑니다.
3. AI가 후보 이미지와 **그 화면이 나오는 동안 화자가 하던 말(자막)** 을 함께 보고, 바로 위 문단 내용을 가장 잘 보여주는 장면(슬라이드·도표·시연 화면 우선)을 고르고 캡션도 이미지에 맞게 다시 씁니다.
   - 맥락에 맞는 정도를 0~3점으로 매겨, **상관없는 화면(0점)은 빼고, 사람만 말하는 화면(1점)은 글 전체 이미지가 2장보다 적을 때만** 남깁니다. 그래서 맥락에 안 맞는 이미지를 억지로 넣지 않습니다.
   - 서로 다른 자리에 같은 장면이 겹치면 AI가 고른 두 번째 후보로 바꿉니다.
   - AI 선택이 실패하면 점수가 가장 높은 후보를 넣습니다.
   - 서버 터미널에 장면마다 고른 시각·점수·이유가 `- 장면 1 [...] → 2:25 fit=3 (...)` 형태로 나와서, 왜 그 장면이 들어갔는지 확인할 수 있습니다.
   - 장면 고르기는 글 하나당 AI 요청이 1~2번 더 들며, 기본으로 글 작성과 같은 Gemini 모델을 씁니다. (한도 초과 시 `gemini-3.5-flash-lite`로 자동 전환)
   - 글 작성이 끝난 뒤 장면을 고르는 데 보통 10~30초가 더 걸립니다. 그동안 이미지 자리에 "장면을 고르는 중…"이 표시됩니다.

**에디터별 이미지 붙여넣기**

| 에디터 | 결과 |
|---|---|
| project0 Quill / CKEditor | 붙여넣은 이미지를 project0 서버에 자동 업로드 (에디터의 기존 업로드 기능 사용) |
| 티스토리 등 | 대부분 그대로 들어감 |
| 네이버 블로그 | 이미지가 빠질 수 있음 → **이미지 저장**으로 받아서 직접 올리기 |

> ⚠️ 영상 장면은 원작자의 저작물입니다. 출처(참고 영상 링크)를 꼭 남기고, 필요한 만큼만 사용하세요.
>
> 유튜브가 바뀌어 캡처가 실패하면 yt-dlp를 최신으로 업데이트하세요: `yt-dlp -U`

## 5. 환경변수 (.env)

| 이름 | 기본값 | 설명 |
|---|---|---|
| `GEMINI_API_KEY` | — | **[무료]** Gemini API 키 |
| `ANTHROPIC_API_KEY` | — | [유료] Claude API 키 |
| `AI_PROVIDER` | 자동 | `gemini` 또는 `claude`. 비워두면 키가 있는 쪽 사용 (둘 다 있으면 Gemini) |
| `PORT` | `3000` | 서버 포트 |
| `GEMINI_MODEL` | `gemini-3.8-flash` | Gemini 기본 모델 |
| `GEMINI_FALLBACK_MODEL` | `gemini-3.5-flash-lite` | 기본 모델의 무료 한도 초과·서버 혼잡 시 **자동으로 넘어갈 예비 모델**. 비우면 사용 안 함 |
| `GEMINI_VISION_MODEL` | `GEMINI_MODEL`과 같음 | 영상 장면을 이미지로 보고 고를 때 쓰는 모델. 한도 초과·서버 혼잡 시 `gemini-3.5-flash-lite`로 자동 전환. 무료 한도를 아끼려면 `gemini-3.5-flash-lite`로 지정 (대신 판단이 덜 정확함) |
| `CLAUDE_MODEL` | `claude-opus-5-5` | Claude 모델 |
| `CLAUDE_EFFORT` | `high` | Claude 작성 노력 수준: `low` / `medium` / `high` / `xhigh` / `max` |
| `YTDLP_PATH` / `FFMPEG_PATH` | 자동 | 장면 캡처 프로그램 위치. 비워두면 `bin/` 폴더 → 시스템 PATH 순서로 찾음 |

### Gemini vs Claude

| | Gemini (무료) | Claude (유료) |
|---|---|---|
| 비용 | 무료 (분당·일일 한도 있음) | 15분 영상 1건에 약 $0.1~0.3 |
| 속도 | 빠름 | 보통 (꼼꼼하게 생각한 뒤 작성) |
| 글 품질 | 충분히 좋음 | 구성·문장 완성도가 더 높음 |

부담 없이 Gemini로 시작하고, 품질이 더 필요하면 `.env`에 `ANTHROPIC_API_KEY`를 넣고 `AI_PROVIDER=claude`로 바꾸면 됩니다.

## 6. 문제 해결

| 증상 | 해결 방법 |
|---|---|
| `Gemini API 키가 설정되지 않았습니다` | `.env` 파일이 프로젝트 폴더(`/home/youtubeToBlog/.env`)에 있는지, `GEMINI_API_KEY` 값이 들어갔는지 확인 후 **서버 재시작** |
| `Gemini API 키가 올바르지 않습니다` | 키를 다시 복사해 붙여넣기 (앞뒤 공백 주의) |
| `Gemini 무료 사용량 한도를 초과했습니다` | 분당 한도면 1~2분 뒤, 일일 한도면 다음 날 다시 시도. (예비 모델로 자동 전환을 이미 시도한 뒤에 나오는 메시지입니다) |
| `Gemini 모델을 찾을 수 없습니다` | Google이 모델 이름을 바꾼 경우입니다. https://aistudio.google.com/docs/models 에서 최신 Flash 모델 이름을 확인해 `.env`의 `GEMINI_MODEL`에 입력 |
| 시작 메시지에 `장면 캡처: 사용 불가` | yt-dlp / ffmpeg 설치 후 서버 재시작 ("영상 장면 캡처 설정" 참고) |
| 미리보기에 `장면을 불러오지 못했어요` | `yt-dlp -U`로 업데이트 후 다시 시도. 서버 터미널의 `[캡처 실패]` 메시지에 원인이 나옵니다 |
| `사용할 수 있는 자막이 없습니다` | 자막이 없는 영상입니다. 자막(자동 생성 포함)이 있는 다른 영상으로 시도 |
| `로그인이 필요한 영상` | 연령 제한·비공개·멤버십 영상은 지원하지 않습니다 |
| `EADDRINUSE: address already in use :::3000` | 3000번 포트를 다른 프로그램이 사용 중입니다. `PORT=4000 npm start`처럼 다른 포트로 실행 |
| `process.loadEnvFile is not a function` | Node.js 버전이 낮습니다. 20.12 이상으로 업데이트 |
| 복사 버튼이 동작하지 않음 | `http://localhost`가 아닌 IP 주소(http)로 접속하면 브라우저가 클립보드 접근을 제한할 수 있습니다. 이 경우에도 대체 방식으로 복사를 시도하며, 안 되면 미리보기에서 직접 드래그해 복사하세요 |

## 7. 프로젝트 구조

```
youtubeToBlog/
├── server.js               # Express 서버 (정적 파일 + /api/generate 스트리밍 API)
├── src/
│   ├── youtube.js          # 유튜브 링크 파싱, 영상 정보·자막 가져오기
│   ├── prompt.js           # 블로그 글 작성 지침 (프롬프트)
│   ├── frames.js           # 영상 장면 캡처 (yt-dlp + ffmpeg)
│   ├── scenes.js           # 글 맥락에 맞는 장면 고르기 (컷 감지·자막 매칭으로 후보 선정 → 캡처 → AI가 이미지+자막 보고 선택)
```
